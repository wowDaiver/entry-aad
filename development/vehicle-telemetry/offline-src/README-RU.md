# Параметры автомобиля — офлайн-комплект для EntryNav2 146

Это экспериментальный нативный плагин для нашего BMW X3 G01, прошивка
`002_146_002`. Внутри уже собранный ARM-плагин и все ресурсы. Интернет,
GitHub, Docker, pip, brew и компилятор при работе с машиной не нужны.
Нужны этот Mac, уже установленный Python 3, системный SSH и ENET-кабель.
Переносить **всю папку**, а не отдельные скрипты.

Папка личная: сохранены пароль root и ранее проверенный ключ нашего ГУ.
Пароль не выводится в журнал и не передаётся в аргументах команд.
При несовпадении ключа соединение прекращается. Не публиковать весь комплект.
Пароль и SSH-доступ эти скрипты не меняют.

Кандидат ещё не запускался на автомобиле. Сборка и локальные тесты прошли,
но появление пункта, XML, русский текст, iDrive/Back и показания ещё требуют
испытания. Пока это четыре нативных раздела со строками, круговых шкал нет.

## 0. До отъезда — без соединения с машиной

Открыть Terminal и выполнить:

```sh
cd ~/bmw/vehicle-telemetry-offline
sh ./00-local-check.sh
```

Ожидается `LOCAL_OFFLINE_KIT_PASS`. Команда проверяет целостность комплекта,
наличие локальных программ и синтаксис скриптов. Сетевых соединений нет.
Все остальные команды запускать из этой же папки. Повторный запуск сохраняет
прежние `reports/` и создаёт новый отчёт с датой.

## 1. У машины — сначала чтение и проверка

Машина припаркована, питание и ГУ включены. Подключить Mac по ENET, дождаться
штатного меню. IP ГУ по умолчанию `169.254.1.0`; сетевые настройки Mac скрипты
не меняют. Телефонную точку доступа выключать не требуется.

```sh
sh ./01-check-and-capture.sh
```

Preflight проверяет на ГУ три точных SHA собственного
HMI/AppFramework/CoreFramework 146. Библиотеки на Mac не копируются: массовое
чтение отключено после наблюдавшихся перезагрузок ГУ. Затем проверяет файловую систему, прежние попытки
установки и зависимости плагина через loader trace. Файлы на ГУ не устанавливает,
root не перемонтирует, сервисы не останавливает. Рабочая папка передачи — RAM `/tmp`.

Успешные отметки: `LOADER_TRACE_PASS_NOT_PLUGIN_EXECUTION`, `CHECK_PASS_NOT_INSTALLED_BY_THIS_COMMAND`.
При `STOP`, несовпадении ключа/прошивки или незнакомых файлах **не переходить к 02**.
Не отключать StrictHostKeyChecking и не править SHA для обхода проверки.
Прошедший preflight не означает, что датчики уже прочитаны.

## 2. Установить кандидат

Если Android Auto работает, нажать **«Стоп» в его меню** и дождаться завершения.
Скрипт сам AA не останавливает. Затем:

```sh
sh ./02-install.sh
```

Повторяется проверка SHA 146, layout и зависимостей. Файлы публикуются в
`/opt/hmi/data/ro/Plugins/VehicleTelemetry/`; manifest появляется последним.
Устанавливаются только собственные XML, manifest, DSO, два архива ресурсов и
маркер владельца. Небольшой журнал операции находится в
`/var/local/data/VehicleTelemetry146/`. На время записи root переводится в RW,
после проверки возвращается в исходный RO с сохранением флагов.

Нет замены бинарников BMW, файлов/настроек EntryAad или кодировок. Предыдущего
плагина в этой папке быть не должно; неизвестный файл/владелец блокирует запись.
Это новая установка, поэтому исходное состояние — отсутствие нашего пункта;
для возврата достаточно отключить нашу регистрацию. Оригинальный AA сохраняется.

Worker отделён от SSH. При обрыве ENET он может продолжать работу.
Не выключать питание и не перезапускать ГУ во время записи.
Успех: `install_VERIFIED_ROOT_RO_MANUAL_HU_RESTART_REQUIRED`, затем
`FILES=installed`, `ROOT_MODE=ro`, `LOCK=absent`.
`ALREADY_INSTALLED_NO_FILES_CHANGED` означает, что файлы уже совпадают.

## Постоянный запуск и защита от неудачных стартов

`persistent.enabled` включает плагин при каждом старте HMI. Разрешение не
расходуется; `trial-arm` больше не нужен. Перед native allocation guard атомарно
сохраняет boot ID, PID и признак незавершённого старта, удерживает kernel flock.
Через 60 секунд работы HMI dispatcher запуск отмечается здоровым. Штатный destroy
помечает завершение чистым. Новый kernel boot после здорового старта допускается
без ручного перевзвода, в том числе после обычного отключения питания автомобиля.

Два подряд незавершённых ранних старта блокируют третью активацию файлом
`persistent.disabled`. Повторные нечистые перезапуски HMI в том же kernel boot
также учитываются, даже если HMI работал больше минуты. Явная ошибка factory/init/
нативного приложения блокирует следующий запуск сразу. Ошибка loader до factory
этим guard не покрыта. Поздний полный reset ядра после здорового старта неотличим
по этой записи от штатного отключения питания и сам по себе не считается сбоем.

Обычное повторение установки не очищает `persistent.disabled`. После срабатывания
нужно сохранить причину и выполнить известный откат либо отдельно разобрать сбой.
`05-disable.sh` убирает регистрацию и `persistent.enabled`, не удаляет ресурсы.
Журналы `trial.log` и `trial.log.previous` вращаются и ограничены примерно 64 KiB
каждый. Там только lifecycle и пять фиксированных неидентифицирующих CDS-свойств.
Демонстрационные показания в физическую сборку не включаются.

## 3. Ручной перезапуск и проверка меню

Только после успешного завершения установки и `ROOT_MODE=ro`, `LOCK=absent`
перезапустить ГУ вручную: удерживать кнопку громкости до перезапуска.
Скрипты команд reboot/restart не отправляют. Дождаться штатного меню, затем:

```sh
sh ./03-status.sh
```

Путь: **Состояние автомобиля → Параметры автомобиля**; новый пункт должен быть
рядом с давлением шин. Разделы: **Двигатель**, **Наддув и топливо**,
**Электрика**, **Движение и АКПП**. Выбирать штатным iDrive; проверить Back из
раздела к корню, затем Back к «Состоянию автомобиля» и возврат к давлению шин.
Открыть/закрыть меню несколько раз, проверить переходы между разделами.

Статус показывает SHA/файлы и отображение DSO в памяти HMI, если оно есть.
Это не доказательство успешного init или работающего интерфейса.
Фактический результат нужно проверить на экране.

Пять свойств CDS дают кандидатов для шести показателей: температура двигателя
и масла, обороты, скорость, средний расход и заряд АКБ. Семантика температуры
двигателя/заряда ещё требует сверки на 146. Для оставшихся восьми источник
пока не найден: «Нет данных» ожидаемо. Не проверять скорость в движении с Mac.
Чтение продолжается всё время видимости меню. Обороты/скорость запрашиваются
не чаще раза в секунду, температура/расход/АКБ — раз в 5 секунд, даже при
отсутствии изменений. Ответы ограничены бюджетом 100 в секунду; превышение
пропускается до нового окна, не отключая подписку навсегда. При выходе
подписки снимаются. Потеря источника по-прежнему даёт «Последние данные».
Ограничения числа открытий нет. Controller переиспользует фиксированное хранилище;
новая подписка получает непрозрачный generation cookie, поздние ответы предыдущих
подписок отбрасываются до обращения к освобождённому/переиспользованному объекту.

## 4. Сохранить результат до следующего перезапуска

Массовый `04-collect.sh` в текущей пробе не запускать. Достаточно
`03-status.sh` и ограниченного журнала `trial.log`.

```sh
sh ./03-status.sh
```

Status сохраняет на Mac состояние файлов, последние строки trial.log и
журналы известных worker. Пункт collect по-прежнему копирует ELF и в текущей
пробе не используется. Сфотографировать меню и записать, что работало/не работало,
время открытия и видимые значения. Все результаты — в `reports/` этой папки.
Ничего автоматически не отправляется; дампы BMW оставить в личном архиве.

## 5. Если пункт не появился, HMI нестабилен или нужен возврат

Сначала дождаться доступности ENET/SSH, затем:

```sh
sh ./03-status.sh
sh ./05-disable.sh
sh ./03-status.sh
```

Ожидается `disable_VERIFIED_ROOT_RO_MANUAL_HU_RESTART_REQUIRED`,
`ROOT_MODE=ro`, `LOCK=absent`, отсутствие активного manifest.
При полных ресурсах статус будет `FILES=disabled`. При частичной установке
может остаться `FILES=partial-or-changed`; успешное отключение означает только
отсутствие регистрации, ресурсы сохраняются для разбора.
После этого вручную перезапустить ГУ и проверить обычное меню/Android Auto.

Отключение переименовывает только известный `VehicleTelemetry.manifest` в
`VehicleTelemetry.registration-disabled`. DSO, XML и ресурсы сохраняются:
они могут быть ещё загружены в HMI. Пункт/плагин могут оставаться активны до
полного ручного перезапуска. Не удалять папки, DSO и lock вручную.
Повторный `05-disable.sh` допустим. Если все ресурсы целы, повторный `02-install.sh`
после проверки снова включает тот же кандидат без замены загруженного DSO.

## После обрыва или старого lock

Начать с `03-status.sh`, а не повторной установки.

- `LOCK=active`: worker ещё существует. Подождать и повторить status; не запускать
  установку, отключение или ручной перезапуск одновременно с ним.
- `LOCK=stale-or-incomplete`: выполнить `sh ./06-recover-lock.sh`. Скрипт сверяет
  владельца, boot ID и время старта PID; живой worker не трогает. Полный старый
  lock переименовывается с сохранением как свидетельство, затем повторить status.
  Неизвестный/неполный lock сохраняется и блокирует работу.
- После освобождения старого lock и при `ROOT_MODE=rw` выполнить `05-disable.sh`:
  он может восстановить RO только по нашему собственному журналу и совпадающему
  разделу. Затем status и ручной перезапуск после подтверждения RO.
- При `ROOT_RO_RESTORE_FAILED`, неизвестных файлах/журнале или неполном lock
  сохранить текст ошибки и `reports/`. Не обходить проверки и не запускать 02
  повторно. Для неполного RAM lock ручной перезапуск допустим только при RO,
  отсутствии работающего worker и завершённой/отключённой регистрации.

Отказ SSH/потеря питания не позволяют гарантировать восстановление скриптами.
Если SSH полностью недоступен, этот комплект не является аварийным загрузчиком.
Неисправное меню не следует считать успешной установкой только по контрольным суммам.

## Что оставить после поездки

Сохранить всю папку с `reports/`, фотографиями и заметками. Для разбора нужны
`result.json`, тексты preflight/status/worker и `firmware/capture.json` вместе
с ELF. Версии исходников и границы локальной проверки — `kit.json` и
`VALIDATION-RU.md`. Никаких подключений к автомобилю при подготовке комплекта не было.

При другом IP команды принимают `--host 169.254.x.x`, например:
`sh ./03-status.sh --host 169.254.1.0`. Принимается только link-local IPv4;
сохранённый SSH-ключ всё равно должен совпасть.
