# Офлайн-маппинг блоков в интерфейс

Единая карта `../source_mapping.hpp` связывает каждую из 31 метрики с источником,
моделью/страницей RHMI и полем главной панели. Из неё берутся ID текстовых моделей
и назначения `PanelData`, поэтому отдельные таблицы интерфейса больше не расходятся.
Для 26 метрик указан источник или расчёт из источника; у пяти источники остаются
неопределёнными. Все поля главной панели имеют привязки либо расчёты. Дополнительные
источники выбирают заряд АКБ и режим S; мощность и рекуперация вычисляются.

Основные привязки:

| Источник | Интерфейс |
| --- | --- |
| CDS engine.temperature / temperature.engine, temperature.oil | Температура и масло |
| CDS engine.RPMSpeed / RPMSpeed | Обороты |
| CDS driving.speedActual / speedActual | Скорость, включая действующий ноль |
| DDE 22 43C2 | Заряд АКБ, байт − 127%; резервный источник CDS sensors.battery |
| DDE 22 48A5 | Момент ДВС, BE16 × 0,11444266 − 2500 Н·м |
| DDE 12 / 0F1FF0, OBD 01 04 | Нагрузка, байт × 100 / 255 |
| DDE 22 5866 | Напряжение, BE16 × 0,001 В |
| DDE 22 43C0 | Ток, BE16 × 0,05 − 1638,35 А |
| EGS 18 / 0F21D0, 22 6000 | Температура АКПП, байт − 40 °C |
| EGS 22 DA2E | Режим P/R/N/D/M и отдельный код передачи; объединение только согласованных выборок |
| EGS 22 DA27 | Положение рычага M/S: свежий код 7 без ошибки шины вместе с D даёт S; M имеет приоритет |
| EGS 22 DA31 | Ручник: BE16 0 = снят, 1 = затянут, прочие значения недействительны; оба состояния проверены на машине |
| DDE 22 40C0 | Первый BE32 / 10 — накопленный заряд IGR-рекуперации в А·с; прирост за два свежих чтения определяет активность за интервал |
| DDE 22 42B9 / 5868 | Давление масла / температура АКБ в подробных разделах |
| EGS DA22 / DA2A / 6009 / 600A / 600C | Блокировка ГТ, валы, турбина, обороты ДВС по АКПП и отдельный код передачи |

Мощность остаётся неизвестной
без свежих момента и оборотов с разницей времён не более 2 секунд. 586F не становится
давлением масла или SoC; ток не определяет рекуперацию, P не определяет ручник.
Обороты EGS 600A не подменяют автоматически CDS-обороты, как и OBD-скорость 010D
не становится неявным запасным источником. 43C2, 48A5 и DA27 добавлены в ограниченный
опрос после проверки F150. CDS255 не затирает независимый заряд из DDE.
DA31 и полный 16-байтный 40C0 также проверены и добавлены в ограниченный опрос.
Рекуперация требует двух полных чтений, 0 < интервал ≤ 3 с и отсутствия ошибки
или сброса счётчика. Неизменившийся счётчик означает отсутствие учтённой IGR-зарядки
за интервал; рост означает её наличие. Длительный разрыв, ошибка, сброс/переполнение
и одиночный архив не дают действующий статус. Устаревший активный статус скрывается.
Это измерение за интервал, а не прочитанный мгновенный режим генератора: точное
совпадение с индикацией Eco Pro пока требует проверки в движении.

## Воспроизведение сохранённых ответов на Mac

Из корня `entrynav2-wireless-aa`:

```sh
python3 development/vehicle-telemetry/dashboard/offline_mapping.py
```

По умолчанию отдельно воспроизводятся пять архивных проходов из
`research/evidence/sensors-source-2026-11-17/` и проход недостающих источников из
`research/evidence/panel-followup-2026-11-18/`, а также два состояния ручника из
`research/evidence/brake-regen-2026-11-18/` (всего восемь отдельных снимков). Из сырых HSFZ-кадров проверяются
адреса, сервис, DID/PID, длина, положительный/отрицательный ответ и F150.
Готовые `interpretation`/`value` из JSON не используются. Затем тот же нативный
декодер заполняет `Model`, общую карту интерфейса и PNG-рендерер.

Результаты в `../build/offline-mapping/`:

- `SOURCE-MAP-RU.md` и `source-map.json`: полная таблица привязок;
- отдельные PNG и JSON для каждого прохода;
- `.events`: компактные проверенные записи для локальной VM, без адресов сети,
  VIN и учётных данных. Это архивные ответы, а не текущие измерения.

У архивов есть время группы, но нет времени каждого измерения. Разные проходы
не объединяются в синхронное состояние автомобиля. На host все записи группы
ставятся в t=0 часов воспроизведения; `--age 6` и `--age 61` позволяют проверить
устаревание и скрытие. Физическое время измерения в отчётах остаётся неизвестным.
Для отдельного архива доступны `--capture FILE.json --out DIRECTORY`.

## Проверка в настоящем HMI изолированной VM

После обновления своей VM по README эмулятора, при работающей VM:

```sh
python3 development/vehicle-telemetry/emulator/console.py --upload \
  development/vehicle-telemetry/build/offline-mapping/live-d83-20261117.events \
  /tmp/telemetry-dashboard-recording
python3 development/vehicle-telemetry/emulator/console.py \
  'printf "recorded\n" > /tmp/telemetry-dashboard-scenario'
```

Открыть «Приборы» или один из подробных разделов. Подпись — **«Офлайн · запись
ответов блоков»**. Просмотр удерживает один архивный снимок на замороженных часах
воспроизведения; новые показания не поступают и временем сейчас не помечаются.
Для смены файла сначала переключить сценарий на `live`, загрузить другой `.events`,
затем снова выбрать `recorded`. Синтетические значения и `PanelExtras` очищаются
при входе в запись, в ней нет CDS-подписок и транспорта к машине.

Файл ограничен 256 событиями и 1400 байтами на строку, диагностический payload —
16 байтами. Чужая идентичность,
неподключённые записи и неправильные длины не заполняют поля. Некорректный или
оборванный файл не применяется частично; при ошибке загрузки экран остаётся без данных.
Записи в `/tmp` исчезают при остановке VM; после нового старта возвращается
обычная синтетическая демонстрация. Физическое ГУ и офлайн-комплекты не меняются.

## Проверки

`../build.py` включает 12 интеграционных тестов маппинга: реальные сырые ответы,
знак тока, нулевую скорость CDS, профильные отказы, независимые ошибки, устаревание,
отсутствие неявных замен источников и соответствие всем страницам/моделям XML.
Отдельный C++-набор с ASan/UBSan проверяет ограниченный атомарный загрузчик записи,
изоляцию идентичностей и отсутствие демоподстановок. `check.py` проверяет PNG,
рендер и сценарии панели. Это офлайн-проверки, они не заменяют проверку на ГУ.
